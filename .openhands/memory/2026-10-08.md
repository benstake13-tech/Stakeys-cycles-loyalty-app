### Scanner (src/components/QRCodeScannerModal.tsx) — root causes
Two real defects, both around the camera lifecycle:
1. **Stale-decode race.** `processCode` awaited `resolveScannedMemberDetailed(rawCode)` (network) and
   then mutated the UI with no way to know the modal had closed / camera flipped / "Scan Next"
   started a new run. A slow lookup landing after close re-opened the result panel on a dead modal.
   Fix: `scanSessionRef` counter. Every `startScanner` / photo-upload / manual-entry / close bumps it
   and captures `const session`. The decode callback ignores frames whose session != scanSessionRef.current,
   and `processCode(rawCode, session)` bails via `isStale()` after the await (before any setState).
2. **Double-start flicker.** A second tap of "Start camera" (or a flip during startup) could create a
   second `Html5Qrcode` on the same `#reader` div. Fix: `startingRef` lock, set before `scanner.start`
   and cleared in `finally`, plus cleared on close.
Tests: qr_code_scanner.test.tsx +2 ("drops a lookup that resolves after the modal was closed",
"can scan again after a stale lookup is superseded by Scan Next").
3. **Wedged duplicate-frame guard.** `handlingRef` was only cleared on open / Scan Next / the
   isOpen effect — a stale photo-upload decode (which returns before reaching the reset) left it
   `true`, so every later scan was silently ignored (scanner looked dead). Fix: `startScanner`
   releases `handlingRef` for the new run; the stale path no longer touches it (clearing it there
   could clobber a run still in flight).
