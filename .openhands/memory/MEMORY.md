# Project Memory — Stakeys Cycles Loyalty App

React 19 + Vite + TS + Supabase loyalty/rewards app for a bike shop.

## Key facts
- `UserProfile` primary key is `uid` (NOT `id`). `CustomerBike` has `category/categoryLabel/brand/model/...`, optional `scrapedData`, `aiIdentification`.
- `addCustomerBike(bike)` adds to the *current user's* garage (`ShopContext.tsx`). `addCustomerBikeForUser(userId, bike)` adds to any user's garage — use this for staff-side flows. Both optimistically update `users`/`currentUser` then persist via `insertCustomerBikeToDb`.
- AI Bike Identifier: `src/components/AiBikeIdentifier.jsx` (uses `useShop`). Vision backend `src/api/visionService.js` uses `@google/genai` structured JSON output. Reads `import.meta.env.VITE_GEMINI_API_KEY`; shows a graceful "not configured" state when unset. Optional `addBike` prop overrides the default persistence (used by staff dossier).
- `SegmentedTabs` / `SegmentedTab` shared component in `src/components/SegmentedTabs.tsx`, used by CustomerPortal + StaffPortal nav.
- Discount-code system (2026-10-03): pure logic in `src/utils/discountService.ts` (`validateDiscountCode`, `computeDiscountAmount`, `findDiscountCode`, `computeSaleTotals`, `roundMoney`, `voucherToDiscountState`, `promotionToDiscountCode`). Types `DiscountCode`/`SaleTransaction`/`SaleDiscountState` in `types/bikeShop.ts`. Persistence `discount_codes` + `counter_sales` in `backendDataService.ts`; context CRUD `discountCodes`/`sales`/`addDiscountCode`/`updateDiscountCode`/`deleteDiscountCode`/`refreshDiscountCodes`/`completeSale`/`recordDiscountUsage`. UI: `DiscountCodesTab.tsx` (staff tab `discount_codes`) + `CounterSaleTab.tsx` (staff tab `till`). The till re-derives the discount via `useMemo` on every basket change (do NOT store a stale `amountOff`). Scanner recognises discount codes when a scan isn't a member.
- `roundMoney` uses the exponential-shift trick (`Number(Math.round(Number(\`${v}e2\`)) + 'e-2')`) because the naive `Math.round(v*100)/100` mis-rounds 1.005 → 1.00.
- Seasonal theme: cross-account via shared Supabase row `app_theme_config(id=1, theme)` (values none|halloween|christmas|easter|cny|valentines), realtime `theme_changes`. UI `StaffThemeSelector.tsx` (StaffPortal); animation `SeasonalThemeCanvas.tsx` (rewritten to an atmospheric "mischief" engine — sky/ground/parallax backdrop/weather + cycling characters doing wheelies, skids, snowball fights, falling off laughing). Mounted in `App.tsx` as z-0 sibling of content (z-10). No `SEASONS` second export (breaks Fast Refresh).
- Counter sale vouchers: `SaleTransaction.discountSource` ('discount_code'|'voucher'|'promotion') + `discountVoucherId`; `processSale` consumes EITHER `recordDiscountUsage` OR `redeemServiceVoucher`, never both (double-count fix).
- `tsc --noEmit` is CLEAN (0 errors) and `vite build` passes.

## Environment / tooling quirks
- LIVE SUPABASE SCHEMA DRIFT (root cause of "spin the wheel" + stamp card not persisting). Project `lhojocpygcnkxvkrcuxh`. `profiles` was missing `stamps/completed_cards/merit_points/last_spin_date/last_stamped_at` (42703) and table GRANTs to anon/authenticated (42501) → spins/stamps never persisted; `last_spun_at` DID exist. `stamp_logs` had an older `id uuid`/`user_id`/`staff_id`/`reason` shape missing `action/customer_*` (PGRST204) so history never persisted. Fix: `ensureProfileRowInDb()` (profiles auto-upsert on login + staff-stamp fallback), `insertStampLogToDb()` legacy-schema retry, and `complete_setup.sql` (ADD COLUMN, GRANTs, uuid→text coercion, signup trigger + backfill, seed wheel).
- No `service_role` key anywhere → the sandbox cannot run SQL against the live DB; the user MUST apply `supabase/complete_setup.sql` in the Supabase dashboard SQL Editor. Bash curl snapshot probes to the project DO work; the browser JS `fetch` path cannot reach `*.supabase.co`, so live login can't be exercised locally.
- `service_bookings` drift (2026-10-03 session 2): the live table lacked `approval_status/approved_at/approved_by/declined_at/decline_reason/staff_notes/quoted_price/quote_note/quote_sent_at` (those existed only on `counter_sales`), so Approve/Decline and saved quotes silently failed to persist. Columns added to `complete_setup.sql` (+drift block) and `repair_missing_grants.sql`; `updateServiceBookingInDb`/`fetchServiceBookingsFromDb` map the snake_case columns.
- Auth confirmation links: `mailer_autoconfirm:false` on the live project. supabase-js `detectSessionInUrl` (default on) strips the URL hash BEFORE React effects run — to detect a returning confirmation link, capture it at client construction: `AUTH_LINK_ON_LOAD` exported from `src/lib/supabase.ts` (reads `window.location.href` at module load). `registerCustomerAccount` MUST pass `emailRedirectTo: window.location.origin`, and email must be normalized (trim+lowercase) consistently; never trim the password on login (signup doesn't).
- Tests: `npm test` (vitest, jsdom; includes all `**/*.test.{ts,tsx}`). Suites `wheel_spin`, `stamp_card`, `backend_loyalty`.
- Prize wheel persistence once lived ONLY in localStorage and the spin called a nonexistent `spin_loyalty_wheel` RPC → every spin failed. Now wired to Supabase; default wheel = `DEFAULT_PRIZE_WHEEL` in `src/utils/prizeWheelHelper.ts`, seeds DB when empty.
- `.env.example` key must be `VITE_GEMINI_API_KEY` (key is used in the browser bundle). Never put the secret `GEMINI_API_KEY` in client code.
- npm install needs `--legacy-peer-deps` (react-custom-roulette pins React 18 peer); afterwards `react-is` (recharts) can be pruned → `vite build` fails "Rolldown failed to resolve import react-is".
- `server.ts` registers Vite dev middleware AFTER `/api/*` routes; if added first it swallows API calls and returns index.html.
