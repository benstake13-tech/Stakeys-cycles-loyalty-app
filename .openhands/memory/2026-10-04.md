## Session 11b — Method 2: Supabase Database Webhook + Resend (commit fd45938)

Request: implement "Method 2" — a Database Webhook on `service_bookings` INSERT
pointing at a Supabase Edge Function that emails via Resend, so the workshop alert
is instant and server-side.

Design decision: the app already sent the new-booking email to BOTH customer and
owner from the browser. Rather than duplicate the owner email server-side, I split
the two:
- **Workshop/owner alert → server-side** (this webhook). Fires even when the
  customer's tab closes.
- **Customer confirmation → still client-side** (`dispatchBookingNotifications`),
  because it's tied to the on-screen "request received" state.
`dispatchBookingNotifications` was changed to send ONLY the customer email (owner
send removed) so the workshop isn't double-alerted. It still returns `emailLog`
(owner) + `customerEmailLog` (customer) so the booking keeps both log entries.

New files:
- `supabase/functions/notify-booking/index.ts` — webhook-only edge function.
  Verifies the caller JWT `role === 'service_role'` (base64-decodes the payload;
  platform already verified the signature) and 403s otherwise, so the public anon
  key can't spam it. Reads `app_settings` (owner_email / email_alerts_enabled /
  owner_phone / business_name) via the auto-injected `SUPABASE_URL` +
  `SUPABASE_SERVICE_ROLE_KEY`, maps the `service_bookings` row to the workshop
  alert template (server-side mirror of `generateBookingEmailHtml`), sends via
  Resend. Skips with `{skipped:true, reason}` when no recipient / alerts off.
- `supabase/WEBHOOK_EMAIL_SETUP.md` — deploy steps + Dashboard webhook steps +
  Option B SQL trigger (`pg_net` `net.http_post`, `security definer`) + curl smoke
  test + troubleshooting.
- `booking_notifications_split.test.ts` — asserts the client emails only the
  customer and never the owner, and surfaces customer-send failures.
- `supabase/config.toml` — added `[functions.notify-booking] verify_jwt = true`.
- `SEND_EMAIL_SETUP.md` — clarified send-email is customer/staff only; workshop
  alert is the webhook.

Verification: tsc clean, 29 files / 187 tests, build OK. Edge fn parsed with
esbuild (deno not installed; `tsconfig` excludes `supabase/functions`).

Still requires the user (can't be done from the sandbox): deploy both functions,
set `RESEND_API_KEY`, and create the webhook (Dashboard → Database → Webhooks,
table `service_bookings`, event INSERT, header `Authorization: Bearer <service_role>`).
