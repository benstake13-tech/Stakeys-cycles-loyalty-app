## Session 10 — profile writes, cooldown, login redesign

**Root cause of the "Write stamp / ticket / point balance" failure (and ALL profile writes).**
The live `profiles` table has every balance column and reads fine. The bug was the write:
`updateUserProfileInDb` used `upsert(payload,{onConflict:'id'})`. `profiles.display_name` is
NOT NULL on the live DB, and PostgREST builds an INSERT candidate for an upsert even when the
conflict target row exists — with `display_name` omitted the candidate violates 23502 *before*
conflict resolution. Verified with curl against `lhojocpygcnkxvkrcuxh`:
  - partial upsert -> HTTP 400 `23502 null value in column "display_name"`
  - upsert including display_name -> HTTP 200
  - `PATCH /profiles?id=eq.<id>` -> HTTP 204
So addStamp, wheel spin, staff adjustments and cooldown resets were all silent no-ops.
Fix: PATCH via `update(payload).eq('id',userId).select('id')`; if 0 rows, `ensureProfileRowInDb`
then retry. Verified live: probe write (stamps+1/completed_cards+1/merit_points+1) -> VERIFIED true,
restore -> RESTORED_OK true.

   helpers fall back to -> a spin recorded in one column could be read from the other, bypassing

2. `updateCustomerPoints` accepted `resetDailyRateLimit`/`resetSpinCooldown`, cleared them only in
