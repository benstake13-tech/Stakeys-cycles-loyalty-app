## Session 19c — admin-only push + CRITICAL secret-leak fix

- **SECURITY (root cause):** `src/utils/oauthService.ts` `getClientId()` did `(import.meta as any).env?.[OAUTH_PROVIDERS[p].clientIdEnv]`. Dynamic `import.meta.env[...]` indexing makes Vite inline the WHOLE env object into the public browser bundle — including `VITE_ONESIGNAL_REST_API_KEY`. Proven with a canary build (`VITE_ONESIGNAL_REST_API_KEY=canary_SECRET_123` appeared verbatim in `dist/assets/index-*.js`). Fix: literal `import.meta.env.VITE_GOOGLE_CLIENT_ID` / `VITE_META_APP_ID` switch. Canary build now clean; public ids still inline. Guard test `env_secret_leak.test.ts` scans `src/**/*.{ts,tsx}` (comments stripped) for dynamic env indexing.
  - LESSON: NEVER index `import.meta.env` dynamically — Vite only tree-shakes static member expressions; any dynamic key ships every `VITE_*` value (secrets included) to the client. `vite.config.ts` has no `define`.
- **Push routing:** old `{ segment: 'staff' }` was a dead segment (never created) → staff booking alerts went nowhere.
