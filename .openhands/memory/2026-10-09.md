## Follow-up (2026-10-09) — "can't create a plan / send does nothing" is an OpenHands bug, not this app
User asked to "fix this issue". Investigated: the Stakeys app has NO plan feature
(grep of src for "plan"/planMode/create-plan only hits weather copy + a
planBalanceProbe variable), and the submit-button testid in the report is an
OpenHands UI testid. This is upstream OpenHands/OpenHands#18202 "[Bug]: Send stays
disabled after branching from a user message with prefilled text" (open,
priority:medium, ready-for-dev). Root cause (from the issue triage): the composer
is contentEditable; programmatic prefill (branch-from-message draft restore,
empty-state suggestion chips, + > Macros, header Git-actions Pull) writes
element.textContent WITHOUT dispatching an input event, so CustomChatInput's
canSubmit stays false and Send stays disabled until a character is typed.
Fix PRs already open: #18203 (draft) and #18226 — both unmerged/blocked.
Workaround for the user: after the text is prefilled, press Enter (Enter-to-send
works) or type-and-delete one character; a full reload of a branch also restores
the draft but still needs a keystroke. The OpenHands frontend source is NOT in this
sandbox (only /usr/local/bin/openhands-agent-server + the VS Code server binary),
so the product bug cannot be patched from here.
