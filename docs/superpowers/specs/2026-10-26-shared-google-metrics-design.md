# Always-visible Google Business metrics in staff apps

The owner's goal is to see the shop's latest Google report directly in the staff app without authorising Google independently on each phone. Extend the existing Google screen with a shared shop connection and automatic refresh; avoid paid services and preserve Google/Meta metrics and surface separation.

One server-only singleton table holds the offline Google refresh token and last successful raw report. It has RLS with no client policy and all anon/authenticated privileges revoked. A single action in the existing business dispatcher verifies Supabase JWTs through Auth and checks the trusted profiles role. Staff/admin can read reports; changing the connection or location also requires a verified administrator email in the existing server ADMIN_EMAILS allowlist. Tokens and secrets never appear in responses or APKs. Live profiles role changes are protected by private.guard_customer_profile_fields; do not reapply the legacy broad profiles migration.

The owner links the already-authorised browser connection once. Server reads refresh Google access tokens automatically and cache reports for five minutes. Concurrent refreshes claim a timestamp, and every credential/location change has a fresh connection version. Version-conditional writes reject obsolete results. Cached figures survive temporary Google failures and show last-updated dates and stale/error text. Explicit disconnect/relink/location changes invalidate the old snapshot. Only explicit location selection may change the global shop location.

The client reads the shared report on open, every five minutes while the document is visible, and on focus/online. Unmount, disconnect and superseded requests cannot restore obsolete data. Private business reports are never shown on customer/public website screens. A rebuilt staff APK includes the same reader and needs no per-device Google OAuth session.

External blocker: screenshot confirms My Business Account Management API disabled in Google project 900853061623. Owner must enable Account Management, Business Information and Performance APIs and obtain Google access approval if quota is zero. Until then the UI must show the actionable error and never fabricate metrics. Existing Google consent may need renewing if revoked or expired; the app cannot promise permanent Google permission.
