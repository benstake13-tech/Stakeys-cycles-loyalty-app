# Prompt: create the discount-code system and auto-apply on barcode scan

Two ways to use this file:
1. Paste the **AI prompt** below into the Supabase SQL Editor's AI assistant (or any coding AI) to generate + apply the schema.
2. Or run the ready-made SQL directly: `supabase/migrations/20261003_discount_codes_and_sales.sql`, or the in-app **Service Status** badge → "Copy SQL setup".

App-side behaviour that depends on this schema:

- Staff Portal → **Discount Codes** tab writes to `discount_codes`.
- Staff Portal → **Till** tab scans a member barcode or a discount code. The discount is validated and applied automatically, the basket total is recalculated, and completing the sale writes `counter_sales` and increments `discount_codes.times_used`.

---

## AI prompt (copy/paste)

> You are working on my Supabase Postgres database for a bike-shop loyalty app. I need a discount-code system for the shop till, plus a record of counter sales. Apply everything in the `public` schema.
>
> Create these two tables if they do not already exist:
>
> 1. `discount_codes` — staff-created discount codes (text ids generated by the app).
>    - `id text primary key`
>    - `code text not null` (e.g. STK-10OFF; add a unique index on `UPPER(code)` so case variants can't collide)
>    - `title text not null`, `description text`
>    - `type text default 'percent'` (either `percent` or `fixed`)
>    - `value numeric default 0` (percentage 0–100 when type is percent, otherwise a £ amount)
>    - `status text default 'active'` (`active` | `disabled` | `expired`)
>    - `expires_at timestamptz`
>    - `usage_limit integer` (null = unlimited), `times_used integer default 0`
>    - `assigned_to_uid text`, `assigned_to_membership text`, `assigned_to_name text` (null uid = open to all customers)
>    - `eligible_categories jsonb default '[]'::jsonb` (empty = all vehicle categories)
>    - `minimum_spend numeric`
>    - `created_by text`
>    - `created_at timestamptz default now()`, `updated_at timestamptz default now()`
>
> 2. `counter_sales` — completed over-the-counter sales.
>    - `id text primary key`, `sale_number text`
>    - `customer_id text`, `membership_number text`, `customer_name text`
>    - `items jsonb not null` (array of `{ id, description, category, quantity, unitPrice }`)
>    - `subtotal numeric default 0`, `vat_rate numeric default 0`, `vat_amount numeric default 0`
>    - `discount numeric default 0`, `discount_code text`, `discount_label text`
>    - `grand_total numeric default 0`
>    - `payment_method text default 'unpaid'` (`card` | `cash` | `online` | `unpaid`)
>    - `staff_uid text`, `staff_name text`
>    - `created_at timestamptz default now()`
>
> Then:
> - `GRANT SELECT, INSERT, UPDATE, DELETE ON public.discount_codes TO anon, authenticated;`
> - `GRANT SELECT, INSERT, UPDATE ON public.counter_sales TO anon, authenticated;`
> - `ALTER TABLE public.discount_codes ENABLE ROW LEVEL SECURITY;`
> - `ALTER TABLE public.counter_sales ENABLE ROW LEVEL SECURITY;`
> - Add permissive policies allowing ALL for anon + authenticated on both tables (matching the rest of this app).
> - Add both tables to the `supabase_realtime` publication (skip if already present).
